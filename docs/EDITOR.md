# EDITOR.md — 標準エディタ設計

Phase 1で実装する通常執筆用エディタの設計メモ。原稿用紙モード（縦書き含む）は
`docs/MANUSCRIPT.md` を参照——両者は同じ本文データを異なるビューで表示するだけで、
別のデータモデルを持たない。

## 1. 最優先事項: 日本語IME

- IME変換中（`compositionstart` 〜 `compositionend`）に、自動保存・DOM再構築・
  Reactの強制再レンダリングなど「入力を横取りしうる処理」を実行しない
  （最重要方針#12, 仕様#94）。
- 自動保存のdebounceタイマーは `compositionend` 後の入力停止を基準に開始する。
  変換中の中間状態を保存対象にしない。
- Undo/Redoのスタックは確定入力単位で積む。変換中の1キー入力ごとに積まない。
- Windows上のMicrosoft IME（ひらがな入力・漢字変換・連続変換・BackSpace・Enter・
  Undo）を最優先でテストする（仕様#94）。実機テストはPhase 1のE2E項目に含める。

## 2. エディタ実装方針

- リッチテキストの構造化編集にはTipTap/ProseMirror系を候補とする（技術構成に明記）。
  ただし「Markdown記号を本文に直接見せる方式を強制しない」（仕様#15）——作者が
  自然に文章を書けることを優先し、見出しや強調はUI操作で適用し記号を画面に残さない。
- 本文データはプレーンな構造化テキスト（正規化された文章表現）として保存する。
  原稿用紙・縦書き・横書き・PDFはすべてこのデータから組版した「ビュー」であり、
  エディタ側だけの特殊フォーマットを持たない（`docs/MANUSCRIPT.md` 2章参照）。

## 3. 必須機能（Phase 1スコープ）

- 日本語入力、Undo/Redo、Copy/Paste/Cut/Select All
- 検索・置換
- 見出し・強調・ルビ・傍点（UI操作から適用。本文中に記号を露出させない）
- 改ページ・シーン区切り
- コメント・メモ
- フルスクリーン・Focus Mode

上記のうちルビ・傍点・原稿用紙表示に関わる部分はPhase 2（原稿用紙）と共同設計する。

## 4. Undo/Redo

- 編集操作の基本機能として最初から実装し、以後のどのPhaseでも壊さない
  （最重要方針#13, 仕様#83）。
- AIによる本文変更（Phase 6以降）も同じUndo/Redoスタックに乗せる。AI適用は
  1回のUndo操作で完全に取り消せること。

## 5. 自動保存

- 入力停止後 500〜1500ms 程度でdebounce保存（仕様#61）。
- アプリ終了前、章切り替え時にも保存する。
- 大量のDB書き込みを避けるため、1文字ごとの保存は行わない。
- 保存状態をステータスバーに表示: 「保存中...」「保存済み」「保存エラー」。
- 保存に失敗しても原稿は一時領域（Working Draft、Phase 8で本格実装）に残す設計に
  しておく——Phase 1時点でも「メモリ上の最新本文とDB上の本文は別々に保持し、
  DB書き込み失敗時もメモリ上のデータは消さない」という原則だけは守る。

## 6. キーボードショートカット（Phase 1最低限）

```
Ctrl+S      保存
Ctrl+Z      Undo
Ctrl+Y      Redo
Ctrl+F      検索
Ctrl+H      置換
Ctrl+B      強調 (太字)
Ctrl+Shift+F フルスクリーン/Focus Mode
```

将来ショートカット設定画面を追加できるよう、キー割り当てをコンポーネント内に
直書きせず、`src/hooks` 配下の設定可能なキーマップ経由にする（Phase 1後半〜）。

## 7. パフォーマンス

- 一文字入力ごとに作品全体を再計算しない、AI解析しない、全DB検索しない
  （仕様#90）。文字数・原稿枚数はdebounce後にまとめて再計算する。
- エディタは「今開いている章/シーン」の本文のみを保持し、他章の本文はメモリに
  載せない。

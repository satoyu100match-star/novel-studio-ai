# MANUSCRIPT.md — 原稿用紙モード設計（Phase 2）

このアプリの最重要差別化機能。着手前に必ずこのドキュメントを読むこと。

## 1. 最重要原則: 本文データとビューの分離

> 本文そのものを「400個のinput」で保存してはいけない（仕様#18）。

データモデルは通常の文章として1本のテキスト（構造化データ）で保持する。
原稿用紙は「文章 → 組版 → セル表示」という一方向のビューであり、以下すべてが
**同じ本文データ**から生成される:

```
本文データ (documents テーブル)
   ├─ 通常エディタ表示
   ├─ 原稿用紙表示（横書き／縦書き）
   └─ PDF/DOCX/EPUB Export
```

原稿用紙モード専用の入力欄やセルごとのDBレコードは作らない。編集は常に
通常エディタと同じデータに対して行われ、原稿用紙モードは「表示上の組版結果」
でしかない（組版結果を直接編集させると、通常エディタとの整合性が壊れるため）。

## 2. 組版パイプライン

```
本文文字列
  → 日本語組版ルール適用（禁則処理・ぶら下げ・行頭/行末禁則等）
  → 行分割（1行 = 設定文字数、例 20文字）
  → ページ分割（1ページ = 設定行数、例 20行 = 400字）
  → セル配列（1マス1文字）としてレンダリング
```

- 実装は「文章→組版結果（行・ページの配列）を計算する純粋関数」を
  `src/features/manuscript/typeset.ts`（Phase 2で新設）に切り出し、Reactの
  レンダリングとロジックを分離する。組版ロジックはUIフレームワークに依存しない
  ので単体テストが書きやすい設計にする。

## 3. 設定可能な原稿用紙サイズ

標準: 20文字 × 20行 (400字)。カスタム: 20×40, 30×40, 自由設定（仕様#16）。
サイズ変更は組版パイプラインのパラメータ変更のみで対応し、専用データモデルを
増やさない。

## 4. 原稿枚数表示: 2種類を区別する

- **換算枚数**: 本文文字数 ÷ 400（単純換算）。
- **実際の原稿用紙レイアウト枚数**: 組版パイプラインを実行した結果のページ数
  （改行・改ページ・禁則処理・ページ末尾の空白などにより換算枚数と一致しない）。

両方を別々に表示可能にする（仕様#21）。文字数から安易に「換算枚数のみ」で
確定させない。

## 5. 縦書き対応

- 標準は `writing-mode: vertical-rl` をベースに設計するが、**CSS表示だけに
  依存して編集機能が壊れないよう**、編集用DOMと表示用組版結果を分離する
  （仕様#17）。
- 対応が必要な要素: 縦中横、半角数字・英数字、ルビ、傍点、長音、約物の向き。
- 縦書き・横書きの切替は同じ本文データに対するビュー切り替えであり、データ変換
  や別保存は発生しない。

## 6. 日本語組版ルール

対象: 句読点、鉤括弧、二重鉤括弧、三点リーダー、ダッシュ、括弧、感嘆符、
疑問符、禁則処理、ぶら下げ、行頭禁則、行末禁則。

設定で「厳密／標準／簡易」の3段階を選べるようにする（仕様#19）。段階ごとの
ルールセットの違いは `typeset.ts` 内でプリセットとして定義し、UIからは
プリセット名だけを切り替えられるようにする。

## 7. テスト観点（仕様#95、Phase 2で追加）

以下を横書き・縦書き両方で確認する:

```
「こんにちは」
『こんにちは』
……
――
！？
123
ABC
漢字（かんじ）
```

禁則処理・ぶら下げ・縦中横・ルビ位置の崩れがないことを確認する専用テストを
`tests/` に用意する。

## 8. 印刷・PDF連携（Phase 9で本格実装）

原稿用紙PDF出力（縦書き・ページ番号・タイトル・作者）も同じ組版パイプラインの
出力を使う。組版ロジックをPhase 2で「文章→レイアウト結果」の形に切り出して
おくことで、Phase 9のPDF出力・印刷プレビューが車輪の再発明にならないようにする。
